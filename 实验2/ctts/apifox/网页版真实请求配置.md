## 二、最后一步需要你手动做：装浏览器扩展 ⚠️

你要的「在网页版里真实发请求」还差最后一步，而这步**只能你手动完成**——原因见第三节。

### 为什么必须装扩展

Apifox 网页版运行在浏览器里，受**同源策略 + CORS** 限制：

- 网页域名是 `https://app.apifox.com`，你的接口在 `http://localhost:8081`
- 浏览器不允许网页直接请求 `127.0.0.1` 的回环地址
- 云端 Proxy 也救不了——它跑在 Apifox 服务器上，**碰不到你本机的 localhost**（这是官方明确限制）

所以官方给的方案就是：**装一个浏览器扩展当 Agent**，由扩展（拥有 `host_permissions: *://*/`）代替网页发请求，绕开 CORS。

### 安装步骤（约 1 分钟）

扩展包我**已经帮你下载并解压好了**，路径无中文无空格：

```
下载的 zip：C:\dev\apifox-ext\Apifox-browser-extension.zip
解压后的目录：C:\dev\apifox-ext\ext\output\Apifox-Agent-Chrome
```

在你**日常用的 Edge**（就是你已经登录 Apifox 的那个）里操作：

1. 地址栏输入 `edge://extensions/` 回车
2. 打开左下角**「开发人员模式」**开关
3. 点**「加载解压缩的扩展」**
4. 选择文件夹：`C:\dev\apifox-ext\ext\output\Apifox-Agent-Chrome`
   > 注意：选**这个文件夹本身**，不是它的子文件，也不是那个 zip
5. 加载成功后，**刷新你的 Apifox 网页标签页**（这步不能省，扩展才会被网页识别）

如果扩展显示报错，官方说明是**可以忽略**的，不影响使用。

### 装上之后怎么用

1. 打开项目页 <https://app.apifox.com/project/8881619>
2. 右上角环境选择器 → 选 **本地开发环境**
3. 点接口「接口1：查询实训项目列表」
4. 点底部状态栏的 **「请求代理」** → 选 **「浏览器扩展」**
   > 装好扩展后这里不会再显示「未安装 Edge 扩展」
5. 点**「发送」**，就能看到 CTTS 返回的真实 JSON

> 前提：CTTS 服务在跑。启动命令：
> ```bash
> cd "C:\Users\asus\OneDrive\Desktop\javaweb\实验2\ctts"
> java -jar target\ctts-0.0.1-SNAPSHOT.jar --server.port=8081
> ```
> （**不要用 8080** —— 那个端口被你的 Docker nginx 容器占着）

## 三、为什么我没能替你自动装

我确实按你的要求做了自动化，浏览器也真的驱动起来了，但卡在扩展加载上。过程记录：

1. 用 `agent-browser` + **你本机的 Edge 内核** 启动受控浏览器（省掉了那次 196MB 的 Chromium 下载——它超时失败了）
2. 用 `--profile` 参数做持久化配置，你扫码登录成功后，我**自动完成了整个导入流程**：点导入 → 选「OpenAPI 规范文件」→ 上传文件 → 选维护方式 → 创建并导入
3. 然后用 `--extension` 参数加载 Apifox 扩展，重启浏览器，通过 CDP 检查 target 列表验证

**卡点**：Edge 的 **M137+ 版本出于安全考虑，禁用了 `--load-extension` 命令行开关**。我加了官方给出的绕过参数：

```
--disable-features=DisableLoadExtensionCommandLineSwitch --disable-extensions-except=<扩展路径>
```

CDP target 列表里确实出现了 6 个扩展，但**逐个核对后都不是我们的 Apifox 扩展**（那些是 Edge 自带组件扩展）。最终判定依据是扩展注入到页面的全局变量：

```js
// Apifox 扩展的 adapter.js 会注入这两个全局标记
window.foxAgentCrossRequest
window.foxAgentCrossRequestVersion

// 实测结果
{ hasAdapter: false, chromeRuntime: false }   // 说明扩展根本没加载
```

绕过 Edge 的这个安全限制需要改注册表策略或改 Profile 的加密签名，属于侵入性操作，我没有做。

**另外提醒一件事**：受控浏览器用的是独立配置，跟你日常 Edge 的登录态不互通（这也是为什么当时要你重新扫码）。所以「装扩展 + 发请求」这件事，在**你自己的 Edge** 里做反而最顺——你本来就已经登录着。

## 四、顺带说明：两个环境的区别

| | 我的受控浏览器 | 你自己的 Edge |
| --- | --- | --- |
| 登录态 | 需重新扫码 | **已登录** |
| 装扩展 | Edge 安全策略拦截 | 正常装（开发人员模式） |
| 用途 | 完成接口导入 | **发真实请求** |

导入是账号级的云端数据，所以在哪台浏览器导入都一样——你在自己的 Edge 里刷新一下就能看到那个项目了。
