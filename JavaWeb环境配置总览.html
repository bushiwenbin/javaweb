需要你知道的几件事

1. pnpm 有个坑，本工程最终改用 npm 安装。 pnpm 默认的 isolated 隔离布局要给每个依赖建 Windows 目录联接，在某些受限环境下这一步会静默失败—— pnpm 报告安装成功，但 node_modules/<包名> 是空目录、node_modules/.bin 根本不生成， 于是 npm run dev 报 "run-p 不是内部或外部命令"。我实测复现过，才改成 npm 安装（对应 package-lock.json）。 切回 pnpm 的方法和修复开关都写在 frontend/.npmrc 的注释里。
2. create-vue 脚手架有个版本不一致，我顺手对齐了。 它生成的 package.json 里 eslint-plugin-oxlint@~1.73.0 要求 peer oxlint@~1.73.0，但同一份文件又把 oxlint 写成 ~1.74.0。 pnpm 只当警告，npm 直接报 ERESOLVE 装不上。统一到 ~1.75.0 后正常。
3. 有几个依赖声明要 Node ≥ 24.15.0，你的是 24.14.0。 npm 安装时打了几条 EBADENGINE 警告，不影响使用（实测构建、启动、代理全通）。 真遇到奇怪问题，把 Node 升到最新 LTS 即可。
4. 你机器上原有的 GraalVM 21 没删。 它在系统级 JAVA_HOME 里（C:\JavaSE\graalvm-jdk），现已被用户级的 JDK 17 覆盖。 另外那个 JDK 的 bin 目录里混着一堆练习用的 .java / .class， 建议源码单独开个文件夹，用 javac -d out 指定输出目录。
5. 有一个文件夹需要你手动删一下。 C:\dev\_setup-temp 是我这次调试的残留（含 pnpm 失败安装的副本，约 746MB）。 我这边有安全删除保护，删不掉，你在资源管理器里删掉整个 _setup-temp 文件夹即可。 C:\dev\_downloads 里的 JDK / Maven 压缩包（约 200MB）也可以一并删。
